Research Projects

  • Jun 2023 – Present
    Graduate Research Assistant, William & Mary (advisor: Dr. Oscar Chaparro)
    • Led and contributed to projects with researchers at the University of Central Florida, George Mason University, the University of Minnesota, and the University of Dhaka.
    • Bug report content and AI coding agents (lead; under review at FSE'27)
      Designed the first controlled study of agent repair for Android app bugs, with over 7,500 repair attempts by three agents (Codex, Claude, Qwen) on about 50 bugs in over a dozen report configurations. Steps to reproduce helped all agents, UI hierarchies were the most useful GUI information, and code localization cut the median repair cost by over 30%. Built: a harness that runs agent CLIs headless in sandboxed app copies, validates patches with UI tests on Android emulators, and tracks tokens and cost per attempt; mixed-effects models in R.
    • Agent patch analysis (co-author; under review at FSE'27)
      Validated agent patches and analyzed the root causes of failures across hundreds of attempts. About three-quarters of attempts passed the tests and one in seven matched the developer's fix. Nearly all other passing patches were valid alternative fixes.
    • BugScribe: LLM-based bug report enhancement (lead; under review at MSR'27) paperartifact
      Developed a technique that grounds LLM reasoning in app execution data to enhance incomplete bug reports. Improved steps-to-reproduce quality by up to 84.7% and observed/expected behavior quality by up to 35.2%, and raised an LLM agent's bug reproduction rate by up to 57.7%. Built: a five-stage LLM pipeline (GPT and Claude APIs) over app execution graphs with per-phase token and runtime tracking, and a bug reproduction runner on Mobilerun, an open-source LLM framework for Android devices, that records each run's trajectory and device logs.
    • Burt++: conversational bug-reporting agent (lead; in preparation) code
      A user describes a bug in plain language, and the agent asks targeted follow-up questions grounded in the app's GUI graph until each report element is resolved. Built: a full-stack agent with React, FastAPI, LangGraph, Redis, and Docker Compose, with per-run logs and an LLM-as-a-judge evaluation against human ground truth.
    • AstroBR: assessing reproduction steps (co-first author; ICPC'25) paperartifact
      Combined LLMs with dynamic app analysis to assess steps to reproduce and identify missing steps, outperforming the state of the art by 25.2% and 71.4%.
    • Buggy UI localization from bug descriptions (lead; ISSTA'24) paperartifact
      Introduced a new task and built a benchmark of 228 bug descriptions from 39 Android apps; evaluated text and multimodal models (e.g., SBERT, CLIP), and used the localized screens to rank buggy code up to 12% more accurately.
    • Issue resolution in practice: Mozilla Firefox (lead; ICSE'25; W&M research grant) paperdataset
      Led a team of seven researchers that analyzed 356 Firefox issue reports, built a model of the resolution process and a catalog of 47 resolution patterns, and validated the findings with Mozilla developers.
    • Developer tools: Inceptor, a dashboard for exploring coding agent trajectories (ICSE'27 demo, under review; designed the tool, its annotation codebook, and its evaluation) live demo, and Sprint, an LLM-powered GitHub assistant for issue report management (MSR'25) papercode
    • Finding solutions in issue discussions (lead; major revision at EMSE) papercode
      Compared traditional ML models, pre-trained language models, and LLMs in 68 configurations on 4,917 annotated comments; a fine-tuned LLM found 83.8% of solution-related comments, and a fine-tuned RoBERTa model was nearly as accurate and took minutes rather than days to fine-tune. Built: QLoRA fine-tuning of Llama-3 (4-bit, Hugging Face PEFT) as Kubernetes GPU jobs, and Llama-3 70B prompting with Ollama.
